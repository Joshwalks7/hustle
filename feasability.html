Project Idea

What we are building and why it matters

This project is a cloud-based employment marketplace that connects people who are hiring with people who are looking for work through a simple, profile-driven platform. It is intended to start small with local, short-term jobs such as mowing lawns, tree trimming, and basic handyman work. Employers can post job listings and manage interested candidates, while job seekers can create an “available for hire” profile that shows their skills, work preferences, and a public-facing page. The platform also supports secure in-app messaging so users can connect without sharing personal contact information right away.

2

Main Features (Requirements)

Core capabilities the system must support
  • Users can create an account and log in.
  • Users can create a profile page.
  • Job seekers can mark themselves as “available for hire” and list skills and work preferences.
  • Employers can create a job listing with a title, requirements, and pay.
  • Users can browse and search job listings and available workers.
  • Employers can view who is interested in a job (basic “apply/interest” function).
  • Users can message each other through basic in-app messaging (simple version).
  • Users can leave ratings after a job is completed (basic rating system).
  • Optional: users can pay to promote a listing/profile (can start as a “promoted” tag only for the demo).
MVP strategy: Build job listings + profiles + browse/search first. Add messaging/ratings only if the core flow is stable.

Users and Use Cases

Who uses it and how it works in practice

Main Users

Local employers (homeowners, small businesses) and local workers (students, part-time workers, freelancers).

Example Use

A homeowner posts “Trim two backyard trees,” adds requirements (“bring ladder and trimmer”), and sets pay to “$80 fixed.” A job seeker searches local listings, applies, and messages to confirm timing and details.

Market Feasibility / Competitor Analysis

Where this fits and what differentiates it

Existing Tools

Common options people already use:

  • Facebook Marketplace / local Facebook groups
  • Craigslist
  • Nextdoor
  • Fiverr / Upwork (more remote-focused)

What They Do Well

Strengths we can learn from:

  • Large user bases
  • Posting is usually easy
  • Some have built-in messaging

What’s Missing

  • Structured, consistent job fields (pay, requirements, availability)
  • Clear “hire-ready” profiles for quick local jobs
  • Simple trust signals (ratings) integrated with listings

Why Our App is Better

  • Designed specifically for fast local jobs (not broad classifieds)
  • Searchable skills + availability
  • Basic ratings to reduce wasted time and improve reliability

Tools & Skills Needed

Tech stack and learning plan

Frontend

HTML, CSS, JavaScript (forms, pages, search/filter UI).

Backend / Database

Node.js + Express with a database like Firebase or MongoDB for users, listings, messages, and ratings.

Hosting

Frontend: Netlify or Vercel. Backend: Render or Railway (or similar Node hosting).

Skills & Approach

We have basic web development knowledge but are not advanced in coding. We will rely heavily on AI to generate code, explain errors, and guide setup. We will keep scope realistic and build an MVP first.

Time & Schedule

A semester-friendly plan
  • Plan & Design: 1–2 weeks (finalize features, simple wireframes, data fields).
  • Build Core Pages: 2 weeks (login, profile page, create listing page, browse listings page).
  • Backend + Data Storage: 2 weeks (basic API routes, saving and retrieving listings).
  • Add Core Features: 2 weeks (search, apply/interest, basic messaging).
  • Test & Present: 1–2 weeks (fix bugs, polish UI, demo flows).
  • Total: ~8 weeks (one semester).

Challenges & Solutions

Risks and mitigation strategies

Challenge: Limited coding experience (AI dependence)

We are not highly experienced and will rely heavily on AI for most of the development.

Solution

Keep scope small, build in steps, and test each feature (create listing, view listing, search listings). Use AI for debugging support and document what we build and why.

Challenge: Authentication + database setup

Configuring accounts and data storage correctly can be confusing.

Solution

Use a beginner-friendly approach (Firebase auth or simplified login for demo), follow step-by-step tutorials, and start with user IDs if needed.

Challenge: Messaging and ratings complexity

Messaging systems can expand quickly and cause scope creep.

Solution

Start with a basic system (one thread per job, plain text only) and a simple rating (1–5 stars). If needed, implement these last.

Challenge: Time management

Balancing workloads across other classes and coordinating as a group.

Solution

Divide tasks clearly (UI pages, backend routes, database setup, testing) and do short check-ins. Prioritize MVP completion before extras.

8

Conclusion

Feasibility verdict

Yes, this project is feasible if we focus on a Minimum Viable Product first. The MVP will include accounts, profiles, job listings (title, requirements, pay), browsing/searching, and a basic way to show interest in a job. If time allows, we will add simple messaging and a basic rating system. This project is worth doing because it solves a real local need, and it gives us hands-on experience building a realistic web application with both frontend and backend components while learning with AI support.
